# Repository working rules

- Read `docs/SYSTEM_CONTRACT.md` before changing live-teaching domain behavior. Product direction is maintained outside the repository; do not infer or redefine product semantics from Git history, PR descriptions, spike notes, benchmark reports, or old implementation comments.
- The next-version target is `session-first-surface-design-v1` in `docs/SYSTEM_CONTRACT.md`. Treat the current single-interpreter/single-flight Core path and accepted-text-only production surface as the reviewed baseline to migrate from, not as permanent product architecture. Documentation of a target does not mean the runtime already implements or passes it.
- Preserve one semantic authority and one accepted Core/Cue history. Live and Stage are execution timescales, not competing truth stores: Stage must not become a mandatory approver of ordinary Live changes, and Stage reconciliation must not re-consume already processed evidence or replay expired attention.
- The local Session Coordinator/Working Window owns evidence ordering, unresolved/review obligations, bounded scheduling, dependency/version checks, incremental indexes, recovery and task lifecycle. Do not push deterministic queue/state/index work into LLM prompts merely because a provider can reason about it. Streaming output may prepare work early, but incomplete generation is never semantic acceptance.
- Keep durable lesson knowledge separate from visual attention. Semantic state should not acquire `Active`, `Retained`, persistent `focusId`, viewport, coordinates, renderer-layout fields, Teaching Move labels, representation-media types, or Semantic Space geometry merely to drive presentation. A validated current attention intent over unchanged accepted knowledge may exist as projection state without fabricating a semantic mutation.
- Teaching Representation is non-authoritative. Grounded representation candidates, visual media, and the current Teaching Visual Language working model must not become a second semantic authority or be promoted into Core ontology for implementation convenience. New truth-bearing claims must return through the reviewed semantic authority and grounding path.
- The production display target is a complete decision pipeline: semantic attention neighborhood → grounded candidate production → final form/attention selection → artifact lifecycle → choreography → readable safe-area frame. Do not preselect `TEXT` at the caller merely because accepted text is the current fallback; text is one valid representation, not the permanent default or a forbidden form.
- The current Teaching Visual Language v0.1 is a product-design working model, not a runtime enum or hard contract: ESTABLISH creates or joins a local Semantic Space; RELATE uses graph structure; ORGANISE uses spatial grouping; TRANSFORM makes meaningful steps visible while preserving invariants and identity; COMPARE aligns comparable dimensions and highlights differences. Implementation may support these moves without serializing them into durable lesson state.
- Semantic Spaces are a current Canvas/UI design direction, not semantic truth. Prefer stable identity, membership/local topology, and recognizable relative geography over immutable pixel coordinates. Local growth may minimally displace neighboring spaces to avoid overlap; do not introduce global re-layout or fixed-coordinate invariants merely because an earlier spike used immutable authored homes. Canonical home and temporarily presented position may differ without duplicating knowledge.
- Board, Teaching Cue and Work Surface have distinct semantic/visual lifecycles. Companion Cue occupies screen-space/safe-area UI and must not enlarge Board world bounds merely because it is visible. Work Surface is not a dumping ground for unvalidated model output or failed semantic interpretation.
- Quantitative relationships and truth-critical conditions belong to accepted meaning when the teaching establishes them. A typed math/representation AST can deterministically render accepted meaning but cannot manufacture operands, operators, conditions, units or causal structure that semantic authority did not establish.
- Update executable contracts in place. Do not add product charters, roadmaps, repair diaries, historical amendment stacks, per-run reports, spike narratives, benchmark genealogies, or other competing authority documents to tracked source.
- Repository documentation is limited to executable system contracts, trace behavior, operational runbooks, and reproducible evaluation definitions. Use `docs/SYSTEM_CONTRACT.md`, `docs/TRACE.md`, `docs/RUNBOOK.md`, and `docs/EVALUATION.md` rather than creating adjacent versions.
- Track implementation, reviewed synthetic regression fixtures, and the canonical corpus/manifest required for reproducibility. Generated evaluation results, model outputs, real captions, session traces, timing/integrity summaries, and experiment notes belong in ignored `.cuelayer/`, `artifacts/`, or an explicitly managed external evidence archive.
- Keep one canonical evaluator/CLI per active evaluation contract. Do not copy versioned evaluators/build scripts or regenerate frozen gold as part of routine fixes. A new domain contract requires a new reviewed evaluation identity rather than silently translating old slot-based gold.
- Product/runtime model, semantic policy, schema, deadlines, batching, retries, context projection, and reducer behavior must not change incidentally during documentation/tooling cleanup. Historical event replay compatibility is production behavior, not disposable benchmark history.
- Preserve the separation between Context Window and Semantic Working Window. The Session Working Window is the runtime carrier of teaching continuity and unresolved work, not a fixed-duration buffer or a second durable knowledge store. Context-budget pressure must not be solved by deleting accepted lesson knowledge, unresolved obligations, or renderer history.
- Accepted Support remains semantic history unless a later semantically justified correction, invalidation, or supersession changes it. Visual eviction or virtualization is not semantic deletion.
- Preserve the current Alpha autonomy boundary from `docs/SYSTEM_CONTRACT.md`: CueLayer may autonomously initiate NOTE / QUESTION / TASK / HINT when the relevance, timing, pedagogical-value and productive-work gate is met, and may autonomously correct a concrete factual teacher error only when the stricter evidence-backed correction gate is satisfied. Do not restore superseded blanket prohibitions from older prompts, corpora, issue comments, or agent instructions.
- Paid provider calls, microphone/video playback, and private trace uploads require explicit task authorization. Offline tests do not establish live product acceptance. First-token speed, universal QUIET, clipped layout, lost evidence or a backlog cleared only after teaching ends do not establish real-time success either.
- Work on a feature branch via PR. Do not merge, deploy, rewrite shared history, or modify unrelated user work without authorization.
- Run the checks appropriate to the change. For the current baseline: `npm run typecheck`, `npm test`, `npm run build`, `npm run eval:semantics:validate`, `npm run eval:core:validate`, diff checks where applicable, and `npm run check:repo -- --clean`. Validation must not write tracked source-tree outputs.
